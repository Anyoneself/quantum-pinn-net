# 好文章的写作要素与执行规范

适用于兼顾方法研究与工程应用的中文学术论文。以明确的问题组织全文，用可复核的证据支撑判断，以准确、具体、克制的语言表达。以下章节和篇幅均为起稿建议，正式投稿时按目标期刊要求调整。

## 1. 全文应有一条清楚的主线

**工程需求 → 研究问题 → 数学描述 → 方法设计 → 实验验证 → 机制解释与工程意义 → 适用范围。**

写作时应做到：

- 从具体对象、工作条件和实际困难出发，不以宽泛的行业背景代替研究问题。
- 把工程困难转化为可以检验的方法问题，明确希望改变什么、用什么指标判断。
- 让每个关键设计对应一个问题，让每项主要结论对应一组证据。
- 用同一组实验说明方法是否有效，以及这种变化对工程任务意味着什么。
- 同时讨论收益、代价和成立条件，不预设所有设计都带来正面结果。
- 按论证需要安排章节，不把方法研究与工程应用写成互不关联的两部分。

工程内容不能只出现在引言和结论中。输入输出的定义、模型假设、评价指标、工况选择和结果讨论，都应与实际任务保持联系。

## 2. 一篇好文章必须具备的要素

| 要素 | 应该怎么做 | 判断标准 |
| --- | --- | --- |
| 明确的研究对象 | 定义对象、任务、空间或时间范围、已知信息与待求量 | 读者能准确说出研究解决什么问题 |
| 有依据的研究动机 | 说明现有方法在特定条件下的不足及其影响 | 困难具体，且值得研究 |
| 清楚的贡献定位 | 区分新方法、已有方法组合、工程适配与实验发现 | 能指出相对已有工作的实质变化 |
| 一致的概念体系 | 统一任务名称、变量、单位、符号和指标定义 | 各章节没有偷换概念 |
| 合理的模型假设 | 说明简化条件、排除因素、先验来源及适用范围 | 读者知道结论依赖哪些前提 |
| 可复现的方法 | 写清计算步骤、关键公式、参数、训练或求解流程 | 核心实现不依赖猜测 |
| 有理由的设计取舍 | 解释为何采用某个结构、约束或参数设置 | 选择有推导、实验或成本依据 |
| 透明的数据与协议 | 说明数据来源、处理、划分、选择和使用范围 | 能检查评价是否独立、信息是否混用 |
| 公平且充分的验证 | 配置相关对照、必要消融、重复实验和任务评价 | 证据能够检验所声称的改进 |
| 具体的结果分析 | 报告差异大小、分布、稳定性和不利结果 | 不只罗列表格，也不只展示最好案例 |
| 有分寸的工程解释 | 将指标变化联系到任务要求和使用成本 | 工程意义来自验证，不是宣传性判断 |
| 克制的结论 | 回答研究问题，说明发现与限制 | 不超出数据、工况和比较条件 |
| 可追溯的研究材料 | 核对文献，保留数据、配置、代码与图表生成记录 | 关键事实和结果能够追查 |

这些要素不必各占一节，但应相互对应。题名提出的能力、方法引入的机制、实验检验的内容和结论概括的发现，应属于同一个研究问题。

## 3. 各部分应该怎么写

### 3.1 题名与关键词

题名优先写出研究对象、任务和核心方法。保留能区分研究内容的信息，删去没有证据支撑的评价词。

- 不预先承诺“高精度”“高效率”“普适”等能力。
- 方法名称应反映实际计算过程，不借名称扩大技术含义。
- 研究只覆盖特定范围时，应在题名或摘要中明确。
- 关键词覆盖对象、任务、核心方法和必要的物理背景，可先选取 4-6 个，再按投稿要求调整。

### 3.2 摘要

摘要应能独立说明研究做了什么、如何验证、发现了什么。通常按以下顺序组织成一个紧凑的自然段；期刊另有结构要求时从其要求。

1. 用一至两句交代研究对象和具体困难。
2. 说明核心方法改变了哪个环节，以及该设计如何回应问题。
3. 交代验证数据、主要比较对象和必要的评价条件。
4. 给出最重要的定量结果，写清指标、比较基准和变化方向。
5. 概括方法发现及其任务意义，保留影响理解的关键限制。

摘要不堆叠背景，不只列模块名称，不以“结果表明方法有效”代替具体发现。围绕背景、贡献、创新定位和实测收益展开，不写“工程价值”、应用前景或未来展望。所有数值应能在正文找到，结论强度不得高于正文。没有完成的验证不能写入摘要结果。

### 3.3 引言

引言应逐步回答“为什么研究这个问题”“已有工作还缺什么”“为什么采用这一思路”。

1. 从具体工程需求切入，说明哪些变量、条件或计算环节构成困难。
2. 按解决思路归纳相关研究，比较其假设、适用条件和不足。
3. 选出与研究最接近的方法，明确已有方法尚未解决的具体问题。
4. 将问题转化为研究目标或可检验假设，解释方法选择的理由。
5. 概括本文工作及验证安排，使贡献与后文证据一一对应。

文献分析应服务于研究定位，不逐篇堆积摘要。不用“研究较少”代替问题论证，也不把常见技术的简单组合直接称为理论创新。相关工作较少时可融入引言，确有独立比较需要时再单列章节。

### 3.4 工程问题与数学描述

先把任务定义清楚，再介绍求解方法。

- 说明研究对象、空间或时间范围、工作条件及预测或求解目标。
- 区分可获得的观测、外部条件、先验信息和评价时才可见的参考量。
- 定义输入、输出、变量、单位、索引和计算域。
- 说明物理假设、简化关系、初始条件、边界条件及其依据。
- 将实际任务写成明确的数学问题，说明求解目标与工程需求的对应关系。
- 区分插值、补全、外推和新对象预测，不把不同任务混用。

只有实际使用物理方程时，才将其作为模型约束展开。统计关系、经验先验和平滑要求应按真实含义命名，不能等同于局部守恒定律。理论或工程背景中介绍过的方程，也不能写成已进入训练或求解过程的约束。

### 3.5 方法设计

方法部分既要说明“怎样做”，也要说明“为什么这样做”。

1. 先给出整体流程，交代输入、各计算环节、输出及信息传递关系。
2. 解释核心表示、模型结构或求解策略，突出相对已有方法的实际变化。
3. 对关键设计给出必要的数学定义、推导或技术依据。
4. 写清目标函数各项的计算对象、样本范围、单位处理和实际含义。
5. 说明参数及权重是固定、预设还是可学习，并交代初始化与更新规则。
6. 交代优化器或求解器、停止条件、模型选择规则及推理过程。
7. 对影响结果的超参数给出取值与选择依据；复杂步骤可用伪代码补充。

每个模块应说明所针对的困难，不能只给名称和结构图。标准知识保留理解方法所需的部分，关键差异不能以“类似已有方法”略过。设计理由与已验证性质要分开，合理动机本身不等于效果证明。

### 3.6 实验设计与评价

实验应围绕研究问题安排。先确定要检验的主张，再确定数据、对照和指标。

| 内容 | 必须写清的事项 |
| --- | --- |
| 数据来源 | 实测、公开数据或数值生成；数量、样本单位、范围、分辨率和获取条件 |
| 参考量质量 | 测量误差、数值求解精度、缺失值或噪声处理；不能默认参考量没有误差 |
| 数据处理 | 变换、归一化、筛选、插值及其参数从何处确定 |
| 数据划分 | 按点、对象、时间或工况划分；训练、验证、测试之间的关系及重叠情况 |
| 比较方法 | 基线选择理由、实现版本、调参方式及是否使用相同信息 |
| 比较条件 | 模型规模、参数量、训练预算、停止条件和模型选择规则 |
| 评价指标 | 定义、单位、方向、计算域及其与任务目标的联系 |
| 重复与统计 | 重复次数、随机性来源、统计单位、汇总方式及不确定性 |
| 计算成本 | 硬件、软件环境，以及预处理、训练、调参、后处理和推理的计时范围 |
| 可复核记录 | 数据版本、配置、种子、代码版本、原始输出及汇总规则 |

归一化、校准、后处理和模型选择应说明信息来源，避免测试信息泄漏。模型原始输出与后处理结果分开报告。确需使用额外信息时，应明确其使用阶段并据此界定任务，不能仍按通常的独立测试解释。

检验模块作用时，应尽量控制主干结构、参数量、预算等混杂因素；无法控制的差异应如实说明，不作超出对照设计的因果归因。整体方案比较与单个机制验证应分别解释。

多个随机种子不等于多个独立数据集，同一对象内的大量位置也不自动构成独立重复。统计方法应与样本依赖关系相适应，同时报告效应大小与必要的不确定性，不只给显著性判断。

除总体性能外，按主张安排必要的模块对照、参数敏感性、不同工况及失败案例。代表性案例应有清楚的选择依据，不能只展示最有利的样本。未完成的实验保留在研究计划中，不写成论文发现。

### 3.7 结果分析与工程讨论

每组主要结果围绕一个问题展开，尽量完成以下五步：

1. 交代比较条件和对象。
2. 给出最重要的观察，引用对应图表和数值。
3. 说明差异大小、波动及出现在哪些区域、时段或工况。
4. 结合方法设计讨论原因，并区分直接证据与可能解释。
5. 回到工程任务，说明收益、代价及适用条件。

结果分析应同时关注整体与局部、平均表现与失败情形、精度与成本。多项指标变化不一致时，解释其所代表的不同目标，不强行概括为“全面提升”。

机制判断应有对应诊断或受控实验。只有总体性能差异时，可以报告比较结果，但不能直接证明某个内部机制。

工程意义应具体到已经评价的任务。需要声称满足工程精度或时效要求时，应给出要求的来源及达标依据。数值案例、实验室验证和现场应用的证据范围应明确区分，不能由中间变量的改善直接推断未经检验的安全、产量或经济收益。

### 3.8 结论

结论直接回答研究问题，通常可概括为三至四项主要发现，并交代必要限制。

- 说明方法解决了哪个具体问题，而不是复述实现步骤。
- 给出有代表性的定量比较及成立条件。
- 总结对工程任务的实际意义，以及值得注意的设计取舍。
- 指出证据尚未覆盖的条件，提出与这些不足直接相关的后续工作。

不引入正文没有出现的新实验，不将局部改善扩大为普遍优势，不用宽泛展望代替研究发现。出现不利结果时，结论应如实反映，不能预设模块越多效果越好。

## 4. 图、表、公式与文献怎样配合

### 4.1 图表围绕问题安排

| 图表类型 | 应承担的任务 |
| --- | --- |
| 任务与数据划分图 | 明确对象、已知信息、待求范围及评价位置 |
| 方法结构或流程图 | 展示信息如何进入计算，各环节如何连接 |
| 设置表 | 集中列出复现所需的配置与比较条件 |
| 总体结果表 | 报告主要指标、比较对象、重复结果及不确定性 |
| 模块或机制对照 | 检查具体设计是否产生所声称的作用 |
| 空间、时间或工况分布图 | 展示平均指标掩盖的局部差异 |
| 训练或求解过程图 | 支撑收敛行为、动态权重或优化过程的分析 |
| 敏感性、失败案例及成本结果 | 说明方法的稳定性、使用代价和适用范围 |

按研究需要选择，不要求凑齐所有类型。每张图表应有明确问题，删除重复表达和不支撑结论的装饰性内容。

研究使用神经网络时，正文应实际嵌入与实现一致的网络架构图，并用图注解释输入、特征处理、主干与输出。涉及训练和推理时，应绘制数据处理、参数更新、验证选模和输出流程，区分训练数据、验证数据和最终评价资料的用途。图内采用短模块名和明确连线，不堆叠具体向量、张量维度或运行配置。

- 坐标、单位、色标、图例和子图标识完整；跨方法比较尽量使用一致尺度。
- 图注交代必要条件、样本量及误差条含义，使图表能够基本独立阅读。
- 表格明确指标方向，数值精度与测量或统计精度相称。
- 正文先说明图表回答什么，再分析关键差异，不逐项复述全部数值。
- 定性图像与定量指标分别使用，不能把视觉印象写成未经测量的性质。

### 4.2 公式服务于方法说明

首次出现的符号应定义含义、维度和必要单位。同一符号不要反复改义，正文、图表和公式应保持一致。

关键公式应说明用途、成立条件和计算位置。损失项注明计算样本与归约方式，权重注明来源与更新方法，物理关系注明变量、假设和边界条件。推导详略由方法差异决定，不为增加篇幅而堆放标准公式。

### 4.3 文献与研究材料可追溯

引用应支持相邻的具体判断。优先核对直接提出相关方法或给出证据的研究，准确区分引用对象的发现与自己的解释。

核对作者、题名、年份、刊期、页码或文章号及标识信息，同时核对引用处的技术概述。完整稿应包含不少于30篇真实、去重、已阅读相关成果的研究论文，并在正文中实际引用；每篇记录阅读来源、相关章节、成果及适用边界。仅核对题录或阅读摘要的条目不计入充分阅读数量，不以凑数代替覆盖关键工作。

说明图表来源、数据和代码可获得性，以及必要的作者、基金、利益冲突等信息。受限材料如实交代获取条件，不虚构公开链接或可复现承诺。

## 5. 怎样写得自然、准确、少套话

减少“AI味”的重点是让每句话承载研究信息，不是机械换词、打乱句式或追求文本检测分数。

- 用对象、变量、方法和结果作主语，少用没有具体所指的“本研究通过一系列先进技术”。
- 用“选取”“固定”“比较”“拟合”“求解”等操作性动词，减少“赋能”“深度融合”“全面提升”等评价性表达。
- 比较时补全对象、条件和指标，说明“相对谁、在哪种条件下、改变多少”。
- 直接写关键观察，不让每段都以“由图可知”开头、以“充分证明”结尾。
- 按因果、转折和比较关系组织段落；只有步骤确有先后时才连续使用“首先、其次、最后”。
- 一段集中回答一个问题，长度由内容决定，不刻意追求每节相同段数和整齐句式。
- 专业术语和指标名称保持稳定，不为避免重复而随意替换同义词。
- 将观察、解释和假设分开表达，谨慎使用“证明”“导致”“显著”“鲁棒”等词。
- 删除没有新增信息的总结句，不反复写“具有重要意义”“奠定坚实基础”。
- 把限制放在相关的数据说明和讨论中，关键限制在摘要、结论中保留，不在每段重复同一组提醒。

修改段落时依次检查：这段回答什么问题，提供什么事实，据此能得出多强的判断。没有事实或推理支撑的评价，应补证据或删除。

## 6. 章节安排与篇幅建议

### 6.1 建议结构

```text
题名
中英文摘要与关键词
0 引言
1 工程问题与数学描述
2 方法设计
3 实验设计与评价方法
4 结果分析与工程讨论
5 结论
参考文献
必要的符号说明、数据代码说明及其他声明
```

章节标题应尽量体现具体研究内容，避免全部使用空泛名称。相关工作、讨论和局限性是否单列，取决于内容规模与论证需要；不要重复介绍工程背景，也不要另设一章重复全部实验。

### 6.2 起稿预算

可先按约 **6500 个正文汉字** 安排初稿，再根据证据和期刊要求增减。以下是写作预算，不是篇幅硬指标。

| 部分 | 建议汉字数 | 主要用途 |
| --- | ---: | --- |
| 引言 | 1100 | 工程需求、相关工作、研究问题与贡献定位 |
| 工程问题与数学描述 | 700 | 对象、信息条件、变量、任务和假设 |
| 方法设计 | 1600 | 核心构造、关键推导、设计理由与求解流程 |
| 实验设计与评价方法 | 800 | 数据、划分、对照、预算、指标和重复规则 |
| 结果分析与工程讨论 | 1900 | 主要发现、机制分析、任务意义与设计取舍 |
| 结论 | 400 | 回答研究问题，概括发现和适用范围 |
| 合计 | 6500 | 不含摘要、参考文献及单列符号表 |

这里按汉字估算，不将英文字母、数字、标点和公式符号逐个计作汉字；与文字处理软件的“字数”口径可能不同。正文可包含节标题及中文图表说明，统计时应前后一致。

中文摘要可先按约 300-400 个汉字起稿，再按期刊口径调整。方法和结果应占主要篇幅，优先删去重复背景与一般性知识，不为满足预算省略关键定义、实验条件或不利结果。

图表、公式和参考文献均不设必须达到的数量。内容完整比数量整齐更重要。

## 7. 推荐的写作与修改顺序

1. 用一句话明确研究对象、待解决问题和预期检验的改进。
2. 列出主要主张，为每项主张对应所需数据、对照和评价指标。
3. 整理已完成的实验与图表，区分已有发现、可能解释和待验证问题。
4. 先写任务、方法和实验协议，检查变量、信息来源与计算流程。
5. 根据证据写结果和讨论，再确定能够保留的贡献与结论。
6. 回写引言、摘要和题名，使全文承诺与实际发现一致。
7. 逐段压缩重复内容，核对术语、数值、图表、公式和引用。
8. 完成格式与材料检查后，按目标期刊要求调整篇幅和结构。

写作过程中发现证据不足，应补充验证或收窄主张，不用更强的形容词弥补。没有完成的工作不应通过润色变成已经实现的能力。

## 8. 成稿检查表

- [ ] 题名、摘要、引言和结论回答的是同一个研究问题。
- [ ] 研究对象、任务范围、信息条件和待求量定义明确。
- [ ] 工程困难能够对应到方法设计，而非仅作为背景。
- [ ] 相关工作比较了假设、条件和实质差异。
- [ ] 贡献定位准确，没有把组合、适配或观察夸大为理论创新。
- [ ] 变量、单位、符号及任务名称在全文中一致。
- [ ] 模型假设、物理关系与实际采用的约束对应。
- [ ] 核心设计有理由，关键步骤和参数足以复现。
- [ ] 数据来源、样本单位、处理与划分可复核。
- [ ] 训练、验证、测试、模型选择及后处理没有未披露的信息混用。
- [ ] 基线使用的信息、预算和选择规则足够透明。
- [ ] 模块作用的主张有相应对照，未将混杂差异直接作因果解释。
- [ ] 重复次数、统计单位、效应大小与不确定性报告恰当。
- [ ] 主要结果同时呈现有利与不利情形，案例选择有依据。
- [ ] 图表回答明确问题，编号、单位、色标和正文引用一致。
- [ ] 机制解释区分直接证据、合理推测和待验证假设。
- [ ] 工程意义具体，精度、成本和适用条件的判断有依据。
- [ ] 数值验证、实验室验证和现场应用的范围没有混淆。
- [ ] 摘要与结论中的数值、能力主张均能在正文找到支持。
- [ ] 文献、图表来源、数据代码说明及作者声明真实准确。
- [ ] 删去套话和重复背景后，研究问题、证据与结论仍然完整。

**最终标准：读者能够理解为什么研究、具体怎样完成、凭什么相信结果，以及结论在什么条件下有用。**
