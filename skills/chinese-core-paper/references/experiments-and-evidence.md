# 实验补强与模块扩展

在发现证据不足、补实验或设计扩展模块时使用。目标是回答研究问题，不是制造正面结论。根据研究设计选择适用的验证方式；下述训练、数据划分和模块消融要求只在相关研究中执行。

## 先区分写作缺口和研究缺口

| 缺口 | 应采取的行动 |
| --- | --- |
| 已有结果，但解释、图表或统计不足 | 重新分析真实输出，补诊断图、效应量和结果讨论 |
| 缺少与主张相关的比较 | 增加公平的强基线或受控消融 |
| 声称收敛更稳，但只保留最终指标 | 采集实际训练或求解日志，比较同等条件下的优化轨迹 |
| 总体统计掩盖局部差异 | 补相关分组、有序变量区间和失败案例分析 |
| 声称泛化或稳健，但没有相应测试 | 按研究对象、时间或条件设计独立测试和扰动实验 |
| 方法存在可定位的能力缺口 | 提出可检验的扩展假设，实施最小模块和受控评估 |
| 结果不支持预设贡献 | 检查实现和协议；无错误时收窄或撤回主张，保留负面结果 |

不要把每篇论文变成所有实验类型的合集。优先补能直接决定核心结论的证据。

## 证据台账

对每项主要贡献维护以下关系，可复用已有日志而不重复建档：

```text
主张或假设
对应实现与计算对象
必要的对照、指标和评价条件
实验状态：计划 / 已运行 / 已验证 / 未支持
配置、数据与原始输出位置
汇总方式、结果值及不确定性
对应图表、正文位置与允许的结论强度
```

测试通过只说明某些实现行为正确，不自动证明科研效果。计划、已启动、已完成和已验证不得混用；模拟、合成、实测或现场数据须按来源准确命名。

## 实验协议与执行

1. 明确研究单位和独立性、数据来源、对照条件及分析方案。涉及预测模型时，进一步明确训练验证测试关系、预处理和模型选择规则；归一化、调参、阈值选择或后处理不得偷用测试信息。
2. 选择与研究问题真正相关的强基线或对照，不预设必须采用某一模型类别。不能因对照结果更好就将其移出主比较。
3. 对齐可用信息、评价域、指标、调参机会和合理计算预算；无法对齐时说明差异，不将混杂因素归因于模块本身。
4. 按主张选择重复和统计方案，报告效应大小及必要不确定性。同一对象内的采样点、不同初始化和独立数据集不是同一种重复。
5. 先小规模检查数据处理、关键计算和指标实现；涉及模型训练时，再检查输入输出、损失及优化过程，然后进入正式实验。优先使用已有运行、测试和汇总工具。
6. 保留原始输出、过程记录、配置和失败日志，采用与现有结构相容的独立输出位置，不覆盖既有结果。缓存仅在代码、数据和协议一致时复用。
7. 从原始输出生成表格和图片，核对代表性数值与实现；关键汇总尽量独立复算，不能手改论文中的数值来匹配预期。

随机性保存在可复核记录中；论文正文不罗列种子。必要的重复次数、统计单位、超参数选择原则、停止规则和不确定性仍须简洁交代。效率是贡献时，正文应保留关键硬件及计时范围，其余环境细节放补充材料。

## 何时设计扩展模块

已有结论不充分时，先判断是否只缺验证。增加架构复杂度不是默认补救手段；用户授权补强研究且确有方法缺口时，主动提出并实现与缺口对应的模块，不停留在建议。

实施前写清四件事：

- 哪个已观察问题需要解决，现有方法为什么可能不足。
- 模块改变了什么，可检验的作用路径是什么。
- 预期改善哪个指标或哪类条件下的表现，可能增加哪些代价。
- 什么结果支持该假设，什么结果意味着不支持。

采用现有代码模式，隔离新增代码和输出，保留原方法可运行。先做小规模试验和行为测试，再按资源预算决定是否扩大；涉及昂贵计算、付费服务、新外部数据权限或生产资源时先获得必要授权。

正式比较至少能区分“原方法”和“加入模块后的方法”。对机理或复杂组合的主张，再补必要的独立模块、替代设计、规模或预算控制。只比较最终两行指标，不足以声称内部机制已获证明。

扩展无收益时如实报告，检查合理的实现或协议问题后允许停止；不要不断试到测试集出现提升才报告。用于探索的验证数据与最终确认测试分开，不能事后更换主要指标或只留下最优重复。

## 什么结果可以写入正文

- 已运行并完成核验的结果可以写为发现；未运行设想只能保留在研究计划或明确标注的不足中。
- 强基线领先时，围绕真实的局部优势、成本、机制或失败条件分析，不能写成“全面优于”。
- 定量收益注明比较对象、指标、范围和成立条件；区分绝对差、相对变化和百分点，不混用。
- 机制解释有消融或诊断才可加强措辞；仅凭性能变化应写为可能解释。
- 测试范围之外的应用、经济或安全收益不由代理指标直接推导。

达不到证据要求时交付真实可用的稿件或阶段材料，同时明确缺口和受影响的结论。不能称其已达到可发表水平或保证录用。
